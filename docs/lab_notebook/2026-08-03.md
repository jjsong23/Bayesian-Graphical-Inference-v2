## 1. External-target adjacency vector

### Purpose

A path endpoint does not need to be a member of the signaling-node universe.
Aqp2 was the motivating example. A general target-extension function was
therefore created to characterize an arbitrary mouse protein against every node
already in the graph and append it as one symmetric row and column.

### Method

The target was resolved to a primary mouse gene symbol and UniProt entry. Each
available edge evidence stream was evaluated between the target and all 891
existing nodes. Missing evidence was neutral and left an edge at its prior
value. The original 891 × 891 matrix block was copied without modification; only
the new target row and column were added. The extended graph remained
undirected, symmetric, bounded in [0,1], and zero on the diagonal.

## 2. Ranked path finding

### Basic algorithm

An undirected path finder was implemented for a selected start and target node.
Candidate paths are simple paths, meaning that a node cannot repeat within a
path. Only edges whose probability is strictly greater than the user-selected
cutoff are retained. The default cutoff is 0.5, which excludes neutral baseline
edges.

Paths are ranked by the product of constituent edge probabilities:

$$
S(\pi)=\prod_{(i,j)\in\pi} P_{ij}.
$$

The search minimizes the equivalent additive cost
\(-\sum\log P_{ij}\). The reported product is a ranking score, not a calibrated
probability that the complete biological pathway is correct.

### Signaling-intermediate constraint

The initial unrestricted search could use scaffolds or other proteins that do
not themselves propagate signals as internal nodes. The intermediate policy was
therefore revised. Internal nodes must have at least one mechanistic relay
class:

- GTPase
- GTPase regulator
- kinase
- phosphatase
- phosphodiesterase
- receptor
- receptor regulator
- second messenger
- signaling regulation

The broad classes `signaling_process`, `adaptor_scaffold`, `ligand`, `binding`,
or second-messenger binding do not qualify by themselves. A scaffold-only
protein is excluded as an internal node. A multi-role protein such as a
kinase/scaffold remains eligible through its kinase role. Start and target nodes
are always exempt from the intermediate rule.

## 3. End-to-end graphical workbench

A minimal local browser workbench was built to run the project from end to end.
It is available at `http://127.0.0.1:8765/` while the local server is running and
can be restarted with `gui/run_workbench.ps1`.

### Stage 1: node selection

Users can independently enable, disable, and weight:

- mpkCCD protein abundance
- principal-cell RNA
- PKA-KO kinase activity
- PKA-KO phosphoprotein response

The 20 curated secondary messengers can be included separately. A protein is
selected when at least one enabled, positive-weight node stream is non-neutral.
Node factors are multiplied after exponentiation by their user weights and then
normalized across all 9,170 protein candidates.

### Stage 2: edge characterization

Users can independently enable, disable, and weight:

- mpkCCD localization
- observed-site KinasePredictor
- STRING v12
- HPA primary localization
- HPA high-confidence localization as a mutually exclusive alternative
- OmniPath core
- STITCH v5 secondary-messenger associations
- optional scaffold-mediated closure

The edge prior and output cutoff are configurable. Edge prior odds are
multiplied by each selected Bayes factor raised to the selected weight. Missing
sparse-table entries have BF = 1 and are neutral.

### Stage 3: path finding

Users can enter the start and target, request 1–500 paths, set the maximum hop
count and edge cutoff, and apply the signaling-intermediate policy. All requested
paths are shown in a scrollable table and written to the run folder.

### Reproducibility

Each analysis writes a new immutable directory under `results/gui_runs/` with:

- exact configuration JSON
- node posterior table
- selected-node table
- complete adjacency matrix
- supported-edge list
- ranked paths and constituent path edges when enabled
- intermediate-node eligibility audit
- analysis summary and warnings
- derived-stream audit tables when applicable

## 4. Independent normalization controls

Every dataset received its own threshold control. For complement-of-minimum
streams, `Tq × = 1.00` reproduces the finalized analysis. Values below one lower
the threshold and increase sensitivity; values above one increase stringency.
The multiplier is applied before recalculating the likelihood and Bayes factor.

This applies to scalar and observation-specific thresholds, including
node-specific localization thresholds and site-specific KinasePredictor
thresholds. STRING and STITCH are exceptions because they use reference-score
odds rather than the Gaussian complement kernel. Their controls are labeled
`Ref ×`:

- STRING reference score: 0.041
- STITCH reference/reporting-floor score: 0.150

HPA primary and high-confidence modes remain mutually exclusive. The GUI and run
summaries retain every stream's weight, multiplier, and normalization reference.

### STITCH v5 integration

STITCH v5 mouse protein–chemical links were then integrated. Exact audited
PubChem mappings were used for the curated messenger nodes, and STITCH Ensembl
protein identifiers were mapped through the project's existing STRING node
mapping.

Results:

- Raw STITCH mouse rows scanned: 39,116,252
- Curated messenger nodes: 20
- Messengers found by exact PubChem CID: 14
- Messengers with in-universe edges: 14
- Filtered messenger-related mouse rows: 26,430
- Unique messenger–mouse-protein pairs: 17,010
- In-universe messenger–protein pairs: 1,037
- Pairs above the 0.150 reference score: 1,017

For reported STITCH probability-like score (s), the factor was:

$$
BF=\max\left[1,
\frac{s/(1-s)}{0.150/(1-0.150)}\right].
$$

Alternate chemical records were collapsed to one unordered pair using maximum
combined confidence. Missing STITCH records were neutral. The evidence was
treated as undirected. STITCH combined scores may incorporate experiments,
databases, prediction, and text mining; they are functional-association scores,
not direct-binding probabilities.

Adding STITCH produced 169,414 non-baseline pairs in the default 891-node graph.
Outputs are under
`results/edge_characterization/localization_kinase_predictor_string_hpa_omnipath_stitch/`.

## 6. Incremental graph extension and persistent pair cache

The workbench initially could not add nodes beyond the validated 891-node
catalog. This limitation was removed while preserving the existing graph as an
immutable seed.

When (k) new nodes are added to (n) existing nodes, the engine characterizes
only:

$$
kn+\binom{k}{2}
$$

previously unseen unordered pairs. Raw evidence is stored in the SQLite database
`data/edge_characterization/incremental_edge_cache/edge_pair_cache.sqlite3`.
Later runs rescore cached raw statistics under the selected thresholds and
weights. They do not reread the large source datasets unless an evidence-source
signature changes.

### Validation

Lowering the protein-abundance threshold multiplier to 0.95 selected eight new
proteins, expanding the graph from 891 to 899 nodes. Exactly 7,156 new pairs
were required:

$$
8(891)+\binom{8}{2}=7,156.
$$

The first run characterized all 7,156; the repeat run reused all 7,156. Adding
one more protein later required only 899 additional pairs. Aqp2 was also tested
through this generalized mechanism: 891 incident pairs were characterized once
and subsequently reused.

At the end of the day, the database contained:

- 396,495 immutable seed pairs
- 455,670 cached incremental pairs
- 415 profiled non-seed nodes
- 852,165 total cached pair hypotheses

The large incremental count reflects the day's GUI sensitivity and dynamic-node
validation runs. Pair keys are canonical unordered pairs, so a symmetric matrix
does not cause duplicate database hypotheses.

## 8. Scaffold-mediated triadic closure

### Correction entered 2026-08-04

The degree-adjusted continuous score, noisy-OR aggregation, and empirical
(T_q) conversion originally implemented on 2026-08-03 were subsequently
rejected as unnecessarily complicated and not biologically justified for this
project. They must not be used or reported as the finalized method.

The replacement is a binary, one-pass rule. Only protein nodes can be endpoints
or common scaffolds, and a common node must contain the exact
`adaptor_scaffold` class token. A protein pair qualifies if both proteins have
pre-closure probabilities strictly greater than 0.90 to at least one shared
scaffold:

$$
\exists s:\quad P_{is}>0.90\ \land\ P_{js}>0.90.
$$

Every qualifying pair receives support likelihood 0.90, corresponding to
(BF=0.90/0.50=1.8) relative to the neutral likelihood. Nonqualifying pairs
remain neutral at BF 1. Scaffold degree, anchor strength above the cutoff, and
the number of shared scaffolds do not change the factor. There is no empirical
(T_q), degree penalty, continuous shared-scaffold score, or noisy-OR operation.
Closure remains non-recursive and disabled by default.

### Validation results

- Scaffold-class protein nodes: 195
- Scaffolds with at least two qualifying anchors: 193
- Strong protein–scaffold anchors: 14,308
- Pairs sharing at least one qualifying scaffold: 205,920
- Pairs assigned the fixed non-neutral closure factor: 205,920
- Fixed closure factor: 1.8
- Pairs newly raised above the 0.5 cutoff: 81,323
- Total non-baseline graph edges before closure: 169,414
- Total non-baseline graph edges after closure: 250,737
- Duplicate inferred pairs: zero
- Self-pairs: zero

Every qualifying pair retains its supporting-scaffold list, shared-scaffold
count, fixed likelihood and factor, and pre/post probability in
`results/gui_runs/scaffold_binary_closure_validation_20260804_v2/scaffold_triadic_closure_audit.tsv.gz`.
