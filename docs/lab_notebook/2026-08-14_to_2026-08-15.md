# Lab notebook — 14–15 August 2026

## Scope

This entry records changes made to the Bayesian Graphical Inference project on
14 and 15 August 2026. The work had four connected goals:

1. integrate the contributed temporal path-ranking prototype without replacing
   the current Bayesian graph or path rank;
2. allow node nondetections to count as optional negative evidence;
3. make the local workbench persistent and diagnose connection failures
   correctly; and
4. allow source-eligible but unsupported edge pairs to count as optional
   negative evidence.

Both negative-evidence modes are disabled in the reproducibility default. They
are sensitivity-analysis options and do not silently change the established
891-node baseline.

## 14 August — temporal path validation

### Contributed material and integration decision

The supplied `files.zip` contained a temporal ranking prototype, a sensitivity
script, method notes, and a derived 25-path example. The code was adapted into
the current framework rather than copied over it. In particular, the older
example path table was retained only as review material because the current
workflow now uses ontology-constrained signal-relay nodes and conservative
ontology directionality.

Temporal information was implemented as an optional fourth stage after path
inference. It annotates current paths but does not update node probabilities,
edge probabilities, graph directionality, path-probability products, or the
primary Bayesian path rank. This distinction is important: the temporal result
tests whether a proposed ordering is compatible with the dDAVP time course; it
is not another edge Bayes factor.

### Temporal data processing

Positive replicate reporter pairs were converted to
`log2(dDAVP / vehicle)` at 1, 2, 5, and 15 minutes. Nonpositive or missing pairs
remained missing. Because each site/timepoint had only three replicates, raw
variance was stabilized against an empirical log-intensity-dependent variance
trend:

```text
s_moderated^2 = (d0 * s0^2(intensity) + d * s_raw^2) / (d0 + d)
```

The default prior degrees of freedom are `d0=4`. One representative
phosphosite per gene is chosen by the largest peak moderated absolute t
statistic. The default within-gene Bonferroni correction accounts for searching
across a gene's sites and timepoints; unadjusted selection remains available
only as an explicit legacy-sensitivity option.

For each retained gene, 2,000 normal Monte-Carlo draws are generated from the
timepoint means and moderated standard errors by default. Each draw yields an
absolute-LFC center-of-mass response time. Path summaries include measured-node
coverage, pairwise soft precedence, point Kendall tau-a, a Monte-Carlo Kendall
interval, and a separate `temporal_evidence_rank` when the minimum coverage rule
is met. The interval is described as a parametric Monte-Carlo interval, not a
fully Bayesian credible interval.

### Scientific and implementation corrections

- Missing gene identifiers are excluded instead of being grouped into a
  synthetic `NAN` gene.
- The required Student-t and rank calculations use the project's existing
  NumPy/pandas environment, avoiding a new undeclared SciPy dependency.
- All appended fields use a `temporal_` prefix to prevent schema collisions.
- The original `ranked_paths.tsv` is preserved; temporal annotations are
  written separately to `ranked_paths_temporal.tsv`.
- Progress and cooperative cancellation checks were added between workbook
  sheets and site/gene batches.
- The GUI exposes the variance prior df, significance alpha, Monte-Carlo draw
  count, seed, p-value correction, and minimum scored-node count.
- Browser validation found that HTML numeric-step rules rejected valid decimal
  defaults. The relevant scientific controls now use `step="any"`.

The canonical validation included 6,755 valid phosphosite trajectories, 2,661
measured genes, and 237 genes passing the adjusted gate. Seven of the 25 current
Prkaca-to-Aqp2 paths contained at least two scored nodes, but none contained the
default minimum of three. Consequently, none received an interpretable
temporal evidence rank. This is insufficient temporal coverage, not evidence
against those paths.

New temporal outputs are:

- `ranked_paths_temporal.tsv`;
- `temporal_gene_responses.tsv.gz`;
- `temporal_variance_trend.tsv`; and
- `temporal_validation_summary.json`.

Detailed temporal methods are in `docs/temporal_path_validation.md`.

## 14 August — optional negative node evidence

Node selection previously allowed evidence to be positive or neutral only. A
new global option, `penalize_unobserved`, now permits a dataset-specific
nondetection to counter the node-present hypothesis. The default penalty is BF
0.5 and the accepted range is strictly positive through 1.

For node (i), active stream (k), prior odds (O_i), stream Bayes factor
(BF_{ik}), and user weight (w_k), the update is unchanged:

```text
posterior_odds_i = prior_odds_i * product(BF_ik ^ w_k)
posterior_i      = posterior_odds_i / (1 + posterior_odds_i)
```

The new behavior changes only which BF is supplied for an eligible
nondetection. With the option off it remains BF 1; with the option on it becomes
the configured BF below 1. Out-of-scope hypotheses remain BF 1. Protein, RNA,
phosphoprotein-response, and collecting-duct abundance streams can assess all
protein candidates. The kinase-activity stream can penalize only proteins with
the exact `kinase` ontology class. Curated second messengers are not protein
assay targets and remain outside this penalty.

With a 0.5 prior and unit weight, one BF 0.5 nondetection gives posterior 1/3;
two give 0.2; four give approximately 0.0588. The engine never assigns BF 0,
so a hypothesis can approach zero but is not made irreversibly zero.

The GUI exposes the switch and penalty BF. Node run audits record, per stream,
whether a node was eligible, observed, and penalized, together with source BF,
effective BF, and weighted log BF. In the initial four-default-stream
sensitivity run, selected proteins fell from 871 to 282 and 8,625 of 9,170
candidate proteins fell below the 0.5 prior. This is a sensitivity result, not a
recommended selection rule.

## 14 August — persistent local workbench and error diagnosis

A reported default-run `Failed to fetch` condition was traced to the absence of
a process listening on `127.0.0.1:8765`; it was not a scientific configuration
error. The browser tab had remained open after the Python server exited.

`gui/launch_workbench.py` and the `-Background` option in
`gui/run_workbench.ps1` now launch a detached, health-checked local server and
write PID/log state. Repeated launches reuse an already healthy listener. The
GUI now distinguishes connection loss from HTTP 400 configuration validation:
connection loss reports that the local analysis server is not running and
offers reconnect/reload, whereas actual invalid settings retain the
`Configuration needs attention` heading. Project data are not modified by a
connection failure.

## 15 August — optional negative edge evidence

### Model

Edge characterization now has a separate global option,
`penalize_unsupported`, with configurable `unsupported_bayes_factor` (default
0.5, valid range greater than zero through 1). It uses exactly the same
odds-based update as positive edge evidence:

```text
posterior_odds_ij = prior_odds_ij * product(BF_ijk ^ w_k)
```

An active primary stream contributes its ordinary stored or recomputed factor
when the pair has a non-neutral relationship. When no such record exists, the
stream contributes the configurable BF below 1 only if the pair falls within
that source's explicit eligibility scope. Out-of-scope pairs remain neutral at
BF 1. With prior 0.5, unit weight, and BF 0.5, one eligible unsupported stream
gives posterior 1/3; repeated independent stream penalties multiply the odds
downward. Positive factors from other streams can counter the negative factors.

The resulting edge matrix remains undirected and exactly symmetric. Each
unordered pair is updated once and mirrored into the two matrix cells; diagonal
self-edges remain zero.

### Source-specific eligibility

- **mpkCCD localization:** both proteins must have valid fractionation profiles
  and positive node-specific thresholds.
- **HPA localization:** both proteins must have valid profiles and thresholds
  under the selected primary or high-confidence HPA policy.
- **KinasePredictor:** one endpoint must carry the exact `kinase` class and the
  other must have at least one observed-or-UniProt-annotated phosphosite that is
  scorable by KinasePredictor.
- **STRING:** both endpoints must be protein nodes with valid mouse STRING
  mappings.
- **OmniPath:** both endpoints must be proteins. Absence from OmniPath is an
  optional database-absence assumption and must not be reported as proof of no
  signaling relationship.
- **STITCH:** one endpoint must be a curated messenger represented in STITCH and
  the other must be a STRING-mapped protein.

For incrementally added nodes, cached mpkCCD/HPA profiles and STRING identifiers
extend the relevant scope decisions. The incremental cache does not yet persist
a KinasePredictor “scorable sites but no hits” field. Therefore, an added target
without a validated site-scope flag is conservatively left neutral rather than
being guessed to be a kinase-prediction nondetection.

Scaffold-mediated closure remains positive-only. Failure to share a qualifying
scaffold is not an independent assay nondetection, so no negative closure factor
is generated. Closure is still calculated in one nonrecursive pass from the
pre-closure graph.

The same source-scope logic is applied when an external target is appended. If
an enabled source has no external-target implementation, the target edge remains
neutral for that stream and a warning is retained. Derived scaffold closure is
not reapplied to an external target.

### GUI and audit behavior

Stage 02 now contains:

- `Treat eligible unsupported pairs as evidence against an edge`; and
- `Unsupported-pair BF`.

The BF input is disabled when the option is off. Existing histogram and violin
summaries automatically expose the new lower tail and count edges below the
prior. The analysis summary records the option state, selected BF, total
stream–pair penalty applications, total pairs below the prior, and per-stream
eligible, unsupported, penalized, and explicit-source-BF-below-one counts.

### Initial sensitivity check

Using the validated 891-node graph, all six default primary edge streams,
unit weights, edge prior 0.5, and unsupported-pair BF 0.5 produced:

- 396,495 unique unordered pairs;
- 332,215 pairs below the 0.5 prior;
- 5,456 pairs remaining exactly at the prior;
- 58,824 pairs above the strict 0.5 output cutoff; and
- 1,112,985 stream–pair penalty applications.

The application count exceeds the pair count because the same pair can be an
eligible nondetection in several sources. By comparison, the unchanged default
with negative edge evidence off retains 169,414 pairs above 0.5 in the internal
891-node graph. The large decrease is expected when absence from several
incomplete databases is treated as cumulative negative evidence; it should be
presented as a sensitivity setting, not as validated calibration.

A focused regression used `Prkar2a`, `Actn1`, and `SM_CAMP` with only STITCH
enabled. `Prkar2a–SM_CAMP`, a recorded relationship, rose above 0.5;
`Actn1–SM_CAMP`, an eligible unsupported pair, fell to 1/3; and the out-of-scope
protein–protein pair `Prkar2a–Actn1` remained exactly 0.5. Symmetry and zero
diagonal were preserved.

## Reporting cautions

- Negative evidence is optional and disabled by default.
- Database omission is not experimental proof of no interaction.
- Only source-eligible missing relationships are penalized; missing coverage is
  neutral.
- Node and edge posteriors remain independent binary-model quantities and are
  not normalized across nodes or pairs.
- The default factor 0.5 is a transparent sensitivity parameter, not an
  empirically calibrated false-negative rate.
- Temporal evidence produces a separate validation rank and never changes the
  canonical Bayesian path rank.
