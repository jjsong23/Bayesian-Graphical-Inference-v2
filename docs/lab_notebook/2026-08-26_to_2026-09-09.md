# Lab notebook: 2026-08-26 to 2026-09-09

## Purpose of this development interval

This interval made the Bayesian graphical-inference workbench easier to audit,
more complete as a sensitivity-analysis system, and more biologically useful
for signal-propagation path inference. The underlying scientific separation was
preserved:

- node probabilities describe whether individual participants belong in the
  modeled signaling system;
- symmetric edge probabilities describe whether an unordered pair is related;
- propagation direction is a separate constraint on how a supported edge may
  be traversed during path search; and
- a whole-path product is a ranking score, not a calibrated probability that
  the biological pathway is true.

No large source dataset or generated result was added to Git. Those files remain
in the companion OneDrive archive under the paths described in
`DATA_AND_RESULTS.md`.

## 1. Tq-aware, end-to-end evidence-stream ablation

### Motivation

The earlier sensitivity analyses characterized marginal score distributions and
Tq response curves, but they did not answer the full systems question: what
happens to final nodes, edges, and paths if one evidence stream is removed?
They also emphasized the generic default profile even though the registry
contains optional collecting-duct, selective PKA-subunit, HPA-alternative, and
scaffold-closure streams.

### Implementation

Added `code/sensitivity_analysis/analyze_end_to_end_ablation.py` and its
regression tests. The default `--stream-scope all` evaluates all 12 registered
node streams and all 8 registered edge streams.

For a stream enabled in the supplied configuration, the full model is the
supplied model and the comparator disables that stream. For a stream that is
off, the full model is a matched add-one context and the comparator is the same
context with that stream absent. Mutually exclusive alternatives cannot be
turned on together; an optional alternative therefore replaces the selected
member of its exclusive group. The output records the analysis context so that
these comparisons cannot be mistaken for one artificial all-stream model.

The focal Tq/reference multiplier is evaluated at the configured value and,
where requested, across a bounded stream-specific grid. All non-focal settings
remain fixed. In particular, model weights, non-focal Tq values, priors,
cutoffs, negative-evidence modes, directionality settings, and path parameters
are not changed. Positive-control calibration is not rerun after ablation;
otherwise the optimizer could compensate for the removed source and obscure
its marginal contribution.

Node-stream ablation is propagated end to end: node posteriors and selection are
recomputed, the graph is rebuilt on the changed node set, edge evidence is
reintegrated, directionality is reapplied, and paths are reranked. Edge-stream
ablation holds the selected nodes fixed, then rebuilds the edge matrix,
propagation matrix, and paths.

### Measurements

The analysis reports:

- selected nodes gained or lost;
- posterior shifts for every candidate node;
- supported unique undirected edges gained or lost, counted once per pair;
- the portion of edge loss mechanically caused by removed nodes versus cutoff
  changes among shared nodes;
- exact-route Jaccard similarity between top-path sets;
- path membership, rank, and score changes;
- summed conditional Bernoulli KL divergence in bits,
  `sum D_KL(Bernoulli(p_full) || Bernoulli(p_ablated))`; and
- minimum/maximum effects across the focal Tq/reference grid.

The KL quantity is a conditional posterior-change measure. It is not expected
mutual information and should not be described as information supplied by a
dataset in isolation. Outputs include checkpoint TSVs, compressed detailed
tables, three PNG summaries, `summary.json`, and a generated methods README.

## 2. Per-node and per-edge evidence transparency

### Motivation

The integrated posterior was visible, but the GUI did not make it easy to answer
which sources supported, refuted, or ignored one particular hypothesis.

### Implementation

Added `gui/evidence_inspector.py`, server routes, browser controls, and tests.
After a run completes, the user can enter one node symbol or two edge endpoints
in either order. For every registered evidence stream the ledger reports:

- whether it was enabled;
- support, refute, neutral, or disabled status;
- whether the node/pair was observed and within the stream's valid negative-
  evidence scope;
- the applied Bayes factor;
- the configured or fitted weight;
- the weighted contribution to log2 posterior odds;
- Tq/reference multiplier and normalization metadata;
- fixed-absence or continuous-negative handling; and
- an explanatory note for missing or out-of-scope evidence.

For nodes, the inspector reads the exact contribution columns written to
`node_posteriors.tsv.gz`. For edges, it rescales only the requested unordered
pair from seed or incremental raw evidence and applies the same scope and
negative-evidence rules as the completed configuration. Derived scaffold
closure is read from its run audit.

The backend reconstructs posterior log-odds from the displayed terms and
compares the result with the stored posterior. The GUI explicitly reports
whether this arithmetic reconciliation passes. This prevents a stale or
incomplete ledger from silently appearing authoritative.

Current limitation: evidence-inspection routes resolve completed jobs from the
server's in-memory job registry. Restarting the server does not delete run
files, but the old run must be rerun or a future persistent-run index must be
implemented before it can be inspected through the current API.

## 3. OmniPath propagation directionality

### Biological/modeling decision

OmniPath source-target direction is now used to disallow additional reverse
traversals during path inference. It does not change the undirected Bayesian
edge-existence probability. Activation/inhibition sign is retained as source
metadata and is not presently used in the path score.

Ontology direction rules remain the established first layer. For each supported
pair:

1. A unique ontology orientation is retained even if OmniPath points the other
   way.
2. If ontology is unresolved and OmniPath supports exactly one direction, the
   reverse traversal is removed.
3. If OmniPath supports both directions, or the combined evidence remains
   conflicting, both traversals are retained.
4. Every allowed traversal keeps the original undirected pair probability.

The input is
`data/edge_characterization/omnipath/2026-07-30/raw/omnipath_mouse_core_post_translational.tsv`.
`build_omnipath_direction_evidence` collapses mapped records per unordered pair
while retaining reported directions, record counts, consensus-direction counts,
resources, and references. The standalone path CLI and GUI both expose an
option to disable OmniPath directions while retaining ontology rules.

Directional runs write:

- `propagation_adjacency_matrix.tsv`;
- `ontology_directionality_audit.tsv.gz`;
- `ontology_class_pair_catalog.tsv`;
- `ontology_direction_rules.json`; and
- `omnipath_direction_evidence.tsv.gz`.

In the validated default run, 35,061 of 224,434 supported unique edges were
uniquely oriented (15.6%): 33,720 by ontology only, 813 by OmniPath only, and
528 by both. Ontology retained precedence over 130 opposing OmniPath calls.
187,753 pairs had no direction evidence and 1,620 remained unresolved because
of conflicting direction evidence.

## 4. Interactive merged predicted-network view

### Motivation

Separate ranked path rows do not make shared hubs, repeated relationships, or
alternative branches obvious. The new view overlays the leading paths into one
network.

### Backend representation

`build_path_network_payload` unions up to the first 50 ranked paths. Each node
appears once and retains its node posterior, ontology roles, endpoint status,
path ranks, and mean path position. Each unordered relationship appears once
and retains its edge posterior, all path ranks/traversals that use it, and
whether the propagation matrix permits one or both directions. An arrow is
serialized only when exactly one matrix direction is nonzero. The payload is
included in the GUI result preview and written as `top_path_network.json`.

### Browser behavior

The result panel defaults to Top 10 and offers Top 5, Top 25, or all available
visualized paths. A deterministic nonlinear force layout keeps the start and
target at opposite sides, preserves vertical lanes, and allows shared hubs to
merge. Re-layout changes the deterministic seed.

Node size/fill and edge width/opacity encode evidence magnitude. The magnitude
uses capped absolute log-odds rather than linear distance from 0.5; this keeps
differences visible when top edge posteriors are all near one. Color semantics
are stable: green means posterior above 0.5, red below 0.5, gray near 0.5, and
orange denotes a curated messenger or external endpoint without a Bayesian node
posterior. Exact probabilities are shown when a mark is selected. Direction
arrowheads have fixed screen size so thick high-confidence edges do not create
oversized arrows.

Selecting a node highlights its immediate neighborhood and reports name, node
posterior, ontology roles, and contributing path ranks. Selecting an edge
highlights its endpoints and reports the edge posterior, direction status, and
path ranks. Both interactions are keyboard accessible.

The final default validation run was
`results/gui_runs/20260909_165921_64090200/` in the local results tree. It found
25 paths and merged them into 19 nodes and 38 relationships. Twelve displayed
relationships were uniquely directed; 26 remained unresolved/bidirectional.
Top 10, Top 25, selection, re-layout, and browser-console behavior were checked
interactively; no browser errors or warnings were observed.

## 5. Incremental edge-cache performance

Small dynamic expansions previously scanned and joined against the full
multi-gigabyte SQLite cache. For requests of at most 50,000 incremental pairs,
the cache now uses exact primary-key existence probes and the edge integrator
loads factor rows for the requested pairs only. Larger expansions retain the
set-based temporary-table strategy. This is a performance change only: pair
canonicalization, evidence signatures, factor calculations, and posterior
integration are unchanged.

## Rules that future sessions must preserve

- Do not normalize node probabilities across proteins or edge probabilities
  across pairs.
- Do not treat missing/out-of-scope evidence as negative unless the applicable
  user-selected negative-evidence mode says to do so.
- Do not restore phosphosite-count correction; one qualifying changed site is
  sufficient and the protein inherits its strongest site factor.
- Do not restore scaffold-degree/promiscuity penalties or recursive closure.
- Do not turn propagation direction into an edge-existence update.
- Do not interpret OmniPath direction as activation/inhibition sign.
- Do not call whole-path product scores calibrated pathway probabilities.
- Do not commit licensed/large source data or generated result trees to Git;
